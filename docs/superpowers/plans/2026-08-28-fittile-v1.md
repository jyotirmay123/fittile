# Fitile V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a synchronized, offline-capable fitness and nutrition PWA with a Capacitor Android APK, explainable deterministic and constrained AI workout recommendations, muscle recovery, food/activity tracking, and complete user data export.

**Architecture:** A feature-oriented React/TypeScript client keeps domain calculations pure and writes user actions to IndexedDB before synchronizing them to Supabase. Supabase provides Google OAuth, PostgreSQL with Row Level Security, storage, realtime notifications, and Edge Functions for OpenAI and external nutrition services. The web build is an installable PWA; Capacitor packages the same client for Android and hosts native camera, barcode, and optional Health Connect adapters.

**Tech Stack:** React, TypeScript, Vite, React Router, Dexie/IndexedDB, Supabase JS, Zod, date-fns, i18next, Recharts, Lucide React, Vitest, Testing Library, Playwright, vite-plugin-pwa, Capacitor Android, Deno Supabase Edge Functions, PostgreSQL/PLpgSQL.

**Spec:** `docs/superpowers/specs/2026-08-28-fittile-v1-design.md`

## Global Constraints

- Fitile is not a medical device; every recovery, energy-expenditure, and photo-derived food value must be labeled as an estimate and remain editable.
- Deterministic recommendations are the default and must work offline; AI recommendations are explicit alternatives.
- Google OAuth and cross-device synchronization use Supabase; the app must also start in clearly labeled demo mode when cloud credentials are absent.
- Every user-owned Supabase table must enable Row Level Security and restrict access to `auth.uid() = user_id`.
- OpenAI and third-party API secrets must never be shipped to the client or Android bundle.
- Core logging must write locally first and retain failed operations in an idempotent synchronization outbox.
- The interface is English in V1 but all product copy must use the internationalization layer.
- Mobile navigation has Today, Train, Food, Progress, and Profile; desktop uses the same information architecture in a navigation rail.
- The app must meet accessible contrast, keyboard navigation, reduced-motion, semantic labeling, and 44 px minimum touch-target requirements.
- Production completion requires clean typecheck, lint, unit/integration tests, browser tests, PWA build, Supabase policy tests, and Android debug build when the Android SDK is installed.

## File Map

- `src/app/`: application shell, routes, providers, global error and loading states.
- `src/design/`: tokens and reusable accessible UI primitives.
- `src/domain/`: framework-independent models and health/fitness calculation engines.
- `src/data/`: IndexedDB repositories, demo seeds, synchronization engine, and Supabase adapters.
- `src/features/`: vertically organized product areas: auth, onboarding, today, training, recovery, nutrition, activity, progress, settings.
- `src/integrations/`: browser/native capability boundaries for barcode, camera, Health Connect, and external API calls.
- `supabase/migrations/`: schema, indexes, triggers, RLS policies, and reference-data migrations.
- `supabase/functions/`: protected AI and food-proxy Edge Functions.
- `tests/`: cross-feature integration fixtures, Supabase policy tests, and Playwright journeys.
- `android/`: generated Capacitor Android project plus the Fitile Health Connect plugin implementation.
